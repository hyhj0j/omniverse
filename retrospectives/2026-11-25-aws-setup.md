# AWS로 Omniverse 실습 환경 만들기 — 1일차 회고 (2026-11-25)

## 왜 AWS?
- 과정은 Kit 앱을 써야 하는데, Kit 앱은 **Windows/Linux + NVIDIA RTX GPU**에서만 돌아감 → 맥북으로는 불가
- 그래서 **클라우드의 Windows+GPU 컴퓨터를 빌려** 맥에서 원격으로 접속하기로 함
- 신규 가입 크레딧($100~200) 안에서 해결하는 게 목표

## 오늘 배운 개념

**1. 무료 플랜 vs 유료 플랜**
- 무료 플랜은 GPU 같은 큰 인스턴스를 막아둠 → 유료 플랜으로 전환해야 함
- 전환해도 크레딧이 먼저 차감되고, 다 쓰면 카드로 청구됨 → **예산 알림 필수**

**2. AWS (new) 간소화 환경 → 고급 기능 활성화**
- 새로 가입하면 초보용 간소화 환경이 됨 (리전 고정, Marketplace 없음)
- **고급 기능 활성화**를 해야 Marketplace를 쓸 수 있음 (되돌릴 수 없고, 지출 한도가 사라짐)
- 순서: 업그레이드(유료 플랜) → 고급 기능 활성화

**3. 리전 (Region)**
- AWS 데이터센터의 위치. 대부분의 리소스(인스턴스, 키 페어, 한도)는 **리전마다 따로** 관리됨
- 밴쿠버에서 가까운 **오리건(us-west-2)**을 선택 → 원격 화면 반응이 빠름
- ⚠️ 작업 전 항상 오른쪽 위 리전부터 확인하기

**4. 계정 구조: 관리 계정 vs 작업 계정**
- 활성화하면 조직(Organization)이 생김
  - **관리 계정**: 결제·권한·정책을 관리하는 본부
  - **작업 계정**: 실제 서버를 돌리는 곳
- Marketplace 구독, 한도, 키 페어, 인스턴스는 **계정마다 따로** → 전부 같은 계정(작업 계정)에서 하기

**5. IAM Identity Center = 버지니아 북부**
- 사용자·권한 관리는 "본거지 리전"이 하나뿐 → 이 계정은 **us-east-1(버지니아)**에서만 설정 가능
- 권한 설정은 버지니아에서 하고, 서버 작업은 오리건에서 하기

**6. SCP (서비스 제어 정책)**
- 조직이 계정 위에 씌우는 규칙. **개인 권한보다 우선**함
- 키 페어 오류의 원인: 리전을 **버지니아**에 둔 채 시도 → SCP가 버지니아에서 EC2를 차단하고 있었음
- 교훈: "권한 없음" 오류가 나면 **리전부터 확인**하기
- `FullAWSAccess` 정책은 절대 떼지 말 것 (떼면 모든 작업이 막힘)

**7. 한도 (Service Quotas)와 vCPU**
- 새 계정은 GPU 한도가 0 → 신청해야 함
- 한도는 GPU 대수가 아니라 **CPU 코어(vCPU) 개수**로 셈. g6e.xlarge 1대 = 4 vCPU (최소 단위)
- 첫 신청은 거절됨 (새 계정은 흔한 일) → 목적·사용 시간·비용 관리 계획을 영어로 적어 재검토 요청

**8. 키 페어 (.pem)**
- 원격 Windows의 관리자 비밀번호를 꺼낼 때 쓰는 열쇠 파일
- 맥에서 안 열리는 게 정상. **다시 받을 수 없으니** 안전한 곳에 보관하고 공유 금지
